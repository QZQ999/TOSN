\subsection*{Purpose and scope}
The experiments use publicly released time series. The industrial datasets contain recorded equipment measurements, while the robustness study applies specified numerical changes to observed ETT series. This section identifies the source files and explains how they become forecasting inputs. The released code provides the configurations for training and the saved results used to calculate the repeated-run summaries.

R0 disables the estimated-error input. The ReLU and Softplus configurations enable it, with the historical reference transformation fixed at the identity setting. These configurations are identified separately from the original four-dataset results. The scope of each comparison follows the Experimental Setup in the manuscript.

\subsection*{Obtaining the ETT data}
ETTh1 and ETTm1 are published in the official ETTDataset repository at \url{https://github.com/zhouhaoyi/ETDataset}. The helper downloads the revision recorded in \path{external_versions.json}. Run the following commands from the extracted supporting archive:
\begin{lstlisting}
python reproduction/reproduce.py fetch-data
python reproduction/reproduce.py verify
\end{lstlisting}
The files are placed in \path{external/ett/ETT-small/}. ETTh1 has 17,420 rows and ETTm1 has 69,680 rows. Each contains a date column and seven measured variables. The source versions and checksums in \path{reproduction/data_sources.json} identify the inputs used by the released configurations.

\subsection*{Obtaining the industrial observations}
The Boiler collection is published at \url{https://doi.org/10.6084/m9.figshare.28868849} under a CC0 licence. The source paper is available at \url{https://www.nature.com/articles/s41597-025-05096-4}. It describes 86,400 observations with 30 variables, sampled every five seconds. The file \path{xinan_uncompleted_data.csv} retains missing observations. For the released reconstruction, use \path{xinan_completed_data.csv}, which contains the provider's completed values. Its missing-value treatment is implemented in \path{AutoReg.py}. This choice fixes the source version and adopts the provider's documented completion procedure.

Use all 86,400 rows and all 30 measurement columns in their supplied order. Preserve the completed values and the sampling interval. The preparation checks for finite values and stops for inspection if that check fails. After downloading the file, run:
\begin{lstlisting}
python reproduction/prepare_boiler_input.py --file xinan_completed_data.csv
\end{lstlisting}
If the downloaded CSV also contains a separate timestamp or exported row identifier, name that metadata field with \texttt{--metadata-column}. The helper still requires 30 measurement columns and records their actual headings. It creates \path{external/boiler_reconstruction/boiler_completed.csv}, together with an input record and a training configuration. The zero-based intervals are $[0,60479)$ for training and $[60479,69119)$ for validation, followed by $[69119,86400)$ for testing. Each upper endpoint is excluded. These integers follow the Python calculation described below.

UTSD is available at \url{https://huggingface.co/datasets/thuml/UTSD}. Its authors also provide a NumPy release through \url{https://cloud.tsinghua.edu.cn/f/93868e3a9fb144fe9719/}. Both links appear in the official project at \url{https://github.com/thuml/Large-Time-Series-Model}. The archive \path{UTSD-full-npy.zip} contains the IoT observations under \path{UTSD-full-npy/IoT/baian/}. These observations originate from the machine-log collection described by UTSD.

The selected file, \path{IoT/baian/0.npy}, contains 180,140 observations of 18 variables. Its checksum and archive location are recorded in \path{reproduction/data_sources.json}. After extracting the archive, the following command checks the input file:
\begin{lstlisting}
python reproduction/reproduce.py inspect-iot --file UTSD-full-npy/IoT/baian/0.npy
\end{lstlisting}
For the released reconstruction, select this complete file. Keep every row and all 18 variables in the stored order. The selection fixes the evaluated interval directly. The source contains finite measurements, so the preparation preserves the supplied values and sampling interval.

Prepare this input with the supplied helper:
\begin{lstlisting}
python reproduction/prepare_iot_example.py --file UTSD-full-npy/IoT/baian/0.npy
\end{lstlisting}
The resulting \path{external/industrial_examples/iot_0.csv} is accompanied by \path{input_record.json}, which identifies the source file and the prepared input. Training uses rows $[0,126097)$ and validation uses $[126097,144111)$, followed by testing on $[144111,180140)$. The CSV headings \texttt{v01} through \texttt{v18} preserve the source column positions. An added \texttt{row\_index} supplies ordering information and is excluded from the model inputs. At prediction length 96, the prepared input produces 125,906 training windows and 17,919 validation windows, followed by 35,934 test windows.

Each industrial helper also creates a runnable 96-step iTransformer configuration. It copies the model and training settings from the recorded ReLU configuration \path{relu_ETTh1_iTransformer_h96_s2026}, which enables the estimated-error input. It changes the input path and ordering-column setting, then records the actual length and number of measurement variables. The output directory identifies a fresh industrial run. After installing the dependencies described below and preparing the corresponding source file, run the appropriate command from the repository root:
\begin{lstlisting}
python -m ugma.cli run --config external/industrial_examples/iot_relu_iTransformer_h96_s2026.json
python -m ugma.cli run --config external/boiler_reconstruction/boiler_relu_iTransformer_h96_s2026.json
\end{lstlisting}
The generated paths refer to the machine used for preparation. Regenerate the input and configuration after moving the release to another machine. Full details appear in \path{reproduction/DATA_USE.md}.

These source choices define fresh runs of the released reconstruction. The original records identifying which industrial observations were used are unavailable, along with the corresponding trained models. The named inputs therefore specify a reproducible protocol for new runs, with their results distinguished from the original industrial table entries.

\subsection*{Chronological processing and forecast windows}
For a series of length $N$, the released code computes the training length with Python's \texttt{int(0.7*N)} and the validation length with \texttt{int(0.1*N)}. The remaining rows form the test partition. Each input record gives the exact integer boundaries produced by this calculation, including its floating-point rounding before conversion to an integer. Rows retain chronological order. For each measured variable, the mean and population standard deviation are fitted to training rows and then applied to every partition. A standard deviation below $10^{-6}$ is replaced by one. The ETT date column and the industrial \texttt{row\_index} column supply ordering information and are excluded from the prediction variables.

The observed history has length $P=96$. The R0 comparison evaluates prediction lengths $Q\in\{96,192,336,720\}$. Every target window lies entirely inside its assigned partition. A validation or test history may contain preceding observations. There are $n_{\rm train}-P-Q+1$ training windows and $n_{\rm partition}-Q+1$ validation or test windows. At $Q=96$, ETTh1 has 12,003 training windows and 1,647 validation windows, followed by 3,389 test windows. ETTm1 has 48,585 training windows and 6,873 validation windows, followed by 13,841 test windows. The full counts appear in \path{artifacts/public_dataset_manifest.json}.

\subsection*{Environment and forecasting models}
Use Python 3.11 or later with a suitable PyTorch installation. The recorded public-data runs used Python 3.14.2 and PyTorch 2.11.0 with CUDA 12.8. Their exact package versions are stored in the environment field of each \path{run.json}. PyTorch installation instructions for the selected operating system and GPU are provided at \url{https://pytorch.org/get-started/locally/}. Once PyTorch is available, install the remaining project dependencies:
\begin{lstlisting}
python -m pip install -e ".[test]"
\end{lstlisting}
The initial forecasting models are loaded from the official Time-Series-Library revision recorded in \path{external_versions.json}. Place that repository at the location expected by the adapter:
\begin{lstlisting}
git clone https://github.com/thuml/Time-Series-Library.git external/tslib
git -C external/tslib checkout 4e938a1767106324dd753b2a44832bf870a0252e
\end{lstlisting}
The public comparisons use iTransformer and FEDformer. Their saved configurations specify the model settings and training schedule. The reconstructed correction uses measured sequences and historical matches. Its configuration sets \texttt{topology\_mode} to \texttt{none}. The data loader can calculate statistical relationships, while this setting excludes those relationships from the evaluated correction. The original four-dataset hardware description remains the one reported in the manuscript; individual run records preserve the environment of each additional study.

\subsection*{Preparing and running the recorded configurations}
The catalogue in \path{reproduction/run_catalog.json} identifies 80 R0 runs. They cover both ETT datasets and both forecasting models at four prediction lengths, with five random initializations per setting. The seeds run from 2026 through 2030. A further 20 ReLU configurations and 20 Softplus configurations evaluate the estimated-error input at $Q=96$. Each catalogue entry links an experimental configuration to its saved results.

Generate the configurations with the following commands:
\begin{lstlisting}
python reproduction/reproduce.py configs --group r0
python reproduction/reproduce.py configs --group relu
python reproduction/reproduce.py configs --group softplus
\end{lstlisting}
The exporter copies each configuration from its saved run record. It changes the input-file location and the output directory to match the current machine. The training settings remain identical. Configurations are written under \path{reproduction_outputs/configs/}, and new results are directed to \path{reproduction_outputs/runs/}. For example, the following command reruns one R0 configuration:
\begin{lstlisting}
cd reproduction_outputs/configs/r0
python -m ugma.cli run --config r0_ETTh1_iTransformer_h96_s2026.json
cd ../../..
\end{lstlisting}
The runner trains the initial forecasting model using the training partition and selects its parameters using validation error. It then trains the historical encoder and constructs a reference collection from training windows. The final training stage fits the correction while keeping the initial forecasting model fixed. ReLU and Softplus runs also train the estimated-error module in that final stage. The saved configuration supplies the stopping rule and every loss weight.

The output includes \path{run.json} with configuration details and numerical results. The file \path{checkpoint.pt} stores model parameters, while \path{predictions.npz} stores the evaluated targets and predictions. Retain these files together with \path{data_manifest.json}. The runner can reuse a cached initial model for a matching configuration. Cache keys include the training and validation input values, which keeps paired correction comparisons tied to the same initial forecast. A fresh training run may differ numerically across hardware or library versions; record its environment alongside the new result.

\subsection*{Rebuilding the reported summaries}
The reported repeated-run summaries can be calculated directly from the supplied results:
\begin{lstlisting}
python reproduction/reproduce.py summary
\end{lstlisting}
This command writes \path{reproduction_outputs/summary.json}. For each run, the MAE reduction is $100(E_{\rm initial}-E_{\rm corrected})/E_{\rm initial}$. The script averages these per-run percentages and calculates the sample standard deviation across the five initializations within each setting. From the 80 R0 records, it recovers 49 improvements and a mean MAE reduction of 2.096074\%. It also recovers the reported ReLU SMM rank correlations from \path{paper_evidence/risk_scores_per_seed.csv}. On unchanged ETTh1, the means are 0.0800 for iTransformer and 0.5520 for FEDformer.

The same command checks the delayed-complete-target TAFAS comparison from \path{paper_evidence/tta_per_seed.csv}. Mean MAE is 0.4470 on ETTh1 and 0.3958 on ETTm1 across five runs per dataset. These are the evaluated calibration modules under the manuscript's delayed-target update rule. The comparison's protocol differs from other uses of TAFAS, so the archive retains that specific experiment label. Summary reconstruction uses saved numerical evidence; a fresh prediction-level analysis uses the regenerated model and prediction files.

\subsection*{Additional analyses and controlled changes}
The analysis scripts under \path{scripts/} provide the procedures for the additional comparisons. The script \path{reviewer_followup.py} contains the component comparisons and the score-enabled training variants. The script \path{reviewer_priority_20260911.py} contains the direct score tests and the delayed-target adaptation comparison. The script \path{reviewer_shift_fixed_batch_20260911.py} implements the fixed-batch evaluation used for the ETTm1 shift comparisons. Their accompanying records identify the source run for each analysis. To repeat an analysis, generate the corresponding trained models and predictions, then set the script's input locations to those files.

For the controlled-shift study, the training and validation values stay unchanged. Transformations start at the test boundary. Let $\mu_j$ and $\sigma_j$ denote training statistics for variable $j$, and let $d_j$ alternate between $+1$ and $-1$ across variables. A level change adds $a\sigma_jd_j$ to the test values. An amplitude change uses $\mu_j+(1+a)(x_j-\mu_j)$. A ramp gradually increases the additive change from zero to $a\sigma_jd_j$ over the test interval. The evaluated values of $a$ are 0.5 and 1.0. The transformed test series supplies both prediction histories and targets according to their time indices. These are specified artificial changes applied to observed ETT data. The industrial tables evaluate chronological prediction on recorded equipment observations.
