# U-GMA research code and experiment records

This repository supplies the reconstructed implementation used in the public-data studies, with the configurations and recorded numerical results. The correction combines historical references with a learned adjustment to an existing forecast. The initial forecasting model remains fixed while the correction is trained.

The indexed comparisons contain 80 R0 runs, where the estimated-error input is disabled. Another 20 ReLU runs and 20 Softplus runs enable that input. The scope of each configuration is explicit in its saved record. The original four-dataset tables and these reconstructed comparisons are distinguished in the manuscript.

## Start with the data

Read [Data sources and processing](reproduction/DATA_USE.md) for the official download locations and the exact ETT processing rules. It also documents a verified 18-variable IoT file and an executable input-preparation example.

From the repository root, download the pinned ETT inputs and check the release:

```text
python reproduction/reproduce.py fetch-data
python reproduction/reproduce.py verify
python reproduction/reproduce.py summary
```

The summary command reconstructs the reported values from saved records. It recovers 49 improvements among the 80 R0 runs and a mean MAE reduction of 2.096074%. It also checks the five-run SMM and delayed-target TAFAS summaries. The expected output is written to `reproduction_outputs/summary.json`.

## Run a recorded configuration

Use Python 3.11 or later and install a suitable [PyTorch build](https://pytorch.org/get-started/locally/). The saved run records include the package versions used for the reported experiments. Then install the project and obtain the forecasting models:

```text
python -m pip install -e ".[test]"
git clone https://github.com/thuml/Time-Series-Library.git external/tslib
git -C external/tslib checkout 4e938a1767106324dd753b2a44832bf870a0252e
python reproduction/reproduce.py configs --group r0
```

The exporter copies each saved configuration, updating the data and output locations for the current machine. Use `--group relu` or `--group softplus` to prepare the estimated-error comparisons. A fresh run can then be started as follows:

```text
cd reproduction_outputs/configs/r0
python -m ugma.cli run --config r0_ETTh1_iTransformer_h96_s2026.json
cd ../../..
```

The run produces a configuration and result record alongside its model parameters and evaluated predictions. Historical analysis scripts under `scripts/` retain their recorded paths and input checksums. Replaying those analyses requires the corresponding regenerated model files and an explicit mapping to their new locations. The configuration exporter and summary commands above are portable.

## What is included

Scientific code is in `src/ugma/`. The tests check the data partitions and training protocol. The catalogue `reproduction/run_catalog.json` links the 120 selected configurations to their original records. Additional historical records are retained under `results/`, including earlier unsuccessful jobs. The completed fixed-batch ETTm1 shift runs are identified separately in their manifests. Numerical summaries used in the paper are in `paper_evidence/`.

The scientific source files and the 471 saved run records are preserved byte for byte from the retained archive. Model weights and prediction arrays are regenerated by training. File checksums are listed in `SHA256.json`.

## Scope of the industrial instructions

The data-use document identifies the public Boiler and IoT sources. It explains the manuscript's chronological split and training-set standardization. The verified IoT input example has a recorded file checksum and exact row boundaries. The original industrial file selections and the original industrial model files remain absent from the retained material; the new source example is labelled accordingly.

## External software

`external_versions.json` records the upstream project revisions. Obtain those projects from their official repositories and retain their licence notices. The TAFAS module retained under `external/reviewer_priority/` is used with the delayed complete-target evaluation described in the manuscript.
